# OpenSweep 1.0.1：开机启动修复说明

这是针对交接文档所述问题的修复版。已修复可确认的关闭逻辑和半成品界面；另一台电脑重启后的实际结果尚未验证。

## 怎么用

1. 退出旧版，安装 OpenSweep-1.0.1-setup.exe；或把便携版解压到一个固定目录，再打开 OpenSweep.exe。
2. 第一次以管理员身份运行，进入“开机启动”。如果原来开启了守护，程序会尝试加强旧版已记住的关闭项；出现“再关掉”时点击它，随后点“刷新”核对。
3. 逐项关闭你不需要的入口，或使用“按建议关闭”。同一个软件可能有 Run 项、计划任务和服务等多个入口，单独关闭一个入口不代表关闭全部入口。
4. 在原先有问题的那台电脑重启验证。新版不会强行结束当前正在运行的程序。
5. 如果仍有程序出现，在“开机启动 → 启动诊断 → 复制诊断报告”保留报告。诊断只读取数据，不会修改启动设置。

便携版还可以在其目录打开 PowerShell，运行：

~~~powershell
.\opensweep-cli.exe startup-report --output .\startup-report.json
~~~

报告包含版本、采集与开机时间、当前进程、父进程、命令行、启动入口状态和守护记录。报告保存在本机，不会自动上传。

## 修复内容

- Run 注册表入口：先保留原始命令和注册表类型，再从实际启动位置移出；重新勾选时恢复。
- 启动文件夹入口：移到启动文件夹旁的备份目录，重新勾选时移回；不会覆盖独立重新生成的快捷方式。
- 服务：关闭时设置为“禁用”，避免“手动”服务被其他程序拉起；重新勾选恢复原启动模式和延迟启动设置。依赖该服务的功能可能暂时不可用，当前已运行服务不会被强制停止。
- 计划任务：继续以 Settings.Enabled 为准，并在修改后核对实际状态；未修改成功时显示失败。
- 守护：可识别旧版仅写禁用标记的项，以及保留禁用标记但重新创建的 Run 命令；能看到并处理旧版设为手动的受监控服务。
- 打包：排除被开发环境 PATH 误收集的第三方 ICU，避免图形程序导入 QtCore 时异常。
- 界面：修复启动页构造错误，补齐十种语言；新增可复制完整报告的启动诊断窗口。
- 诊断：不再将“相同路径／同安装目录”当成确定的启动来源；不再漏掉开机 15 分钟以后启动的可见进程。

## 恢复与回退

先在 1.0.1 的“开机启动”页重新勾选相应入口，恢复成功后再更换旧版。旧版不知道新版备份的位置，不能用旧版恢复这些入口。

备份位置：

- Run 和 Run32：对应用户或机器注册表的 Software\OpenSweep\DisabledStartup\Run 或 Run32，保留 REG_SZ / REG_EXPAND_SZ。
- 服务原启动模式：机器注册表 Software\OpenSweep\DisabledStartup\Service。
- 启动文件夹：原 Startup 文件夹的同级目录 OpenSweep Disabled Startup。
- 原源码：随附 OpenSweep-source-before-fix.zip。它是修改前的半成品快照，不是推荐运行的版本。

卸载 OpenSweep 不会主动重新启用已关闭的第三方入口，也不会删除上述恢复备份。

## 已完成的验证

- 91 项自动测试全部通过，覆盖备份失败、恢复、旧设置迁移、多入口、PID 复用和十种语言界面构造。
- 在真实 Windows 上用一次性测试项完成注册表、计划任务、服务的关闭—读取状态—恢复验证；测试项已清理。
- 已检查三套皮肤的启动页与诊断窗口。
- PyInstaller 构建完成；打包后的命令行版本为 1.0.1，实际诊断输出正常。图形守护入口在关闭守护的隔离配置中可正常启动并退出。
- 安装包由 Inno Setup 编译。未在本机实际安装或重启，以免干扰现有软件环境。

## 仍需区分的情况

诊断是“当前仍可见的进程及当前设置”，不是事前记录的完整开机日志。程序可能在关闭入口前已经启动，也可能被其他入口、父程序或 Windows 会话恢复启动；已退出的进程与父进程不能凭现有快照还原。

守护在登录后检查一次，可能晚于其他程序运行；它会尝试重新关闭入口，不会撤销本次已经发生的启动。修改机器级入口仍需管理员权限。
